### 1.2 아키텍처 패턴
- **마이크로서비스 아키텍처**: 각 서비스를 독립적으로 배포 및 확장
- **이벤트 주도 아키텍처**: TTS 생성과 같은 비동기 작업 처리
- **RESTful API + WebSocket**: 실시간 진행률 업데이트 및 협업
- **서비스 디스커버리**: Kubernetes 기반 서비스 탐색 🆕
- **Circuit Breaker 패턴**: 장애 격리 및 복구 🆕
- **CQRS 패턴**: 읽기/쓰기 분리로 성능 최적화 🆕

## 3. 백엔드 설계

### 3.1 마이크로서비스 구조

#### 1) Auth Service (인증 서비스)
- **책임**: 사용자 인증 및 권한 관리
- **기술**: Node.js (Express), JWT
- **엔드포인트**:
  - `POST /api/auth/register`
  - `POST /api/auth/login`
  - `POST /api/auth/logout`
  - `POST /api/auth/refresh-token`

#### 2) Project Service (프로젝트 서비스)
- **책임**: 프로젝트 생성, 조회, 수정, 삭제
- **기술**: Node.js (Express)
- **엔드포인트**:
  - `GET /api/projects`
  - `POST /api/projects`
  - `GET /api/projects/:projectId`
  - `PUT /api/projects/:projectId`
  - `DELETE /api/projects/:projectId`
  - `PATCH /api/projects/:projectId/info` (제목, 작성자, 조회수)

#### 3) Panel Service (패널 서비스) **핵심!**
- **책임**: 패널 생성, 편집, 순서 변경
- **기술**: Node.js (Express)
- **엔드포인트**:
  - `GET /api/projects/:projectId/panels`
  - `POST /api/projects/:projectId/panels`
  - `GET /api/panels/:panelId`
  - `PUT /api/panels/:panelId`
  - `DELETE /api/panels/:panelId`
  - `PATCH /api/panels/reorder` (순서 변경)
  - `POST /api/panels/:panelId/image` (이미지 첨부)

#### 4) TTS Service (TTS 생성 서비스)
- **책임**: 텍스트를 음성으로 변환
- **기술**: Node.js, FFmpeg, Gemini API
- **엔드포인트**:
  - `POST /api/tts/generate`
  - `POST /api/tts/generate-batch` (여러 패널 한 번에)
  - `GET /api/tts/jobs/:jobId`
  - `GET /api/tts/jobs/:jobId/progress`
  - `DELETE /api/tts/jobs/:jobId`

#### 5) Image Service (이미지 서비스)
- **책임**: 이미지 업로드, 저장, 제공
- **기술**: Node.js (Express), AWS S3
- **엔드포인트**:
  - `POST /api/images/upload`
  - `GET /api/images/:imageId`
  - `DELETE /api/images/:imageId`
  - `POST /api/images/:imageId/crop` (크롭/리사이즈)

#### 6) Preset Service (프리셋 서비스)
- **책임**: 프리셋 관리 및 제공
- **기술**: Node.js (Express)
- **엔드포인트**:
  - `GET /api/presets` (프리셋 목록)
  - `GET /api/presets/:presetId` (프리셋 상세)
  - `POST /api/presets/:presetId/apply` (프리셋 적용)

#### 7) Notification Service (알림 서비스)
- **책임**: 실시간 알림 전송
- **기술**: Node.js (Socket.io)
- **WebSocket 이벤트**:
  - `tts:progress` - TTS 생성 진행률
  - `tts:completed` - TTS 생성 완료
  - `tts:failed` - TTS 생성 실패
  - `panel:updated` - 패널 업데이트
  - `project:saved` - 프로젝트 저장

### 4.2 테이블 상세 설계

#### Users 테이블

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    username VARCHAR(100) NOT NULL,
    channel_name VARCHAR(100), -- 채널명 (예: "이게진짜")
    profile_image_url TEXT,
    email_verified BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    subscription_id UUID REFERENCES subscriptions(id),
    
    CONSTRAINT email_format CHECK (email ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$')
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_channel_name ON users(channel_name);
```

#### Projects 테이블

```sql
CREATE TABLE projects (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(500) NOT NULL, -- "에어컨 커튼 요금 폭탄? 이 습관이 원인!"
    author_name VARCHAR(100), -- 작성자명 (채널명과 다를 수 있음)
    view_count INTEGER DEFAULT 0, -- 조회수 (예: 200,000)
    show_author BOOLEAN DEFAULT TRUE, -- 작성자 정보 표시 여부
    status VARCHAR(50) DEFAULT 'draft' CHECK (status IN ('draft', 'in_progress', 'completed')),
    channel_name VARCHAR(100), -- 프로젝트별 채널명
    preset_id UUID REFERENCES presets(id),
    settings JSONB, -- 스타일 설정 등
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    
    CONSTRAINT title_length CHECK (char_length(title) >= 1)
```

### 10.9 타임라인 에디터

#### 타임라인 데이터 구조
```typescript
interface TimelineState {
  panels: TimelinePanel[];
  totalDuration: number;
  currentTime: number;
  zoom: number;
  markers: TimelineMarker[];
}

interface TimelinePanel {
  id: string;
  startTime: number;
  duration: number;
  transition: {
    type: 'cut' | 'fade' | 'slide' | 'zoom';
    duration: number;
  };
  effects: {
    volume: number;
    fadeIn: number;
    fadeOut: number;
  };
}

class TimelineEngine {
  calculateTotalDuration(panels: TimelinePanel[]): number {
    return panels.reduce((total, panel) => {
      return total + panel.duration + panel.transition.duration;
    }, 0);
  }
  
  getPanelAtTime(time: number): TimelinePanel | null {
    let currentTime = 0;
    for (const panel of this.panels) {
      if (time >= currentTime && time < currentTime + panel.duration) {
        return panel;
      }
      currentTime += panel.duration + panel.transition.duration;
    }
    return null;
  }
```

### 10.11 영상 편집 MVP 구현 설계 (2026-05-04)

기존 설계는 장기 확장을 포함한 마이크로서비스 구조를 제시하지만, 현재 코드베이스는 Express + SQLite 기반의 로컬 MVP입니다. 따라서 영상 제작 기능은 먼저 모듈형 모놀리스로 구현하고, TTS/렌더/스토리지 경계를 서비스 모듈로 분리합니다.

#### MVP 아키텍처 원칙

1. 백엔드는 단일 Express 앱으로 유지합니다.
2. Gemini API 키, 파일 저장, 렌더링은 모두 백엔드에서 처리합니다.
3. 프론트엔드는 작업 요청과 상태 표시, 미리보기, 타임라인 편집에 집중합니다.
4. DB에는 생성 결과뿐 아니라 작업 상태와 실패 사유를 저장합니다.
5. 같은 대본/음성/속도/지시문 조합은 hash로 캐시하여 TTS 재생성을 줄입니다.

#### 기능별 서비스 경계

| 기능 | 백엔드 모듈 | 주요 책임 |
|------|-------------|-----------|
| 프로젝트/씬 | `projectService`, `sceneService` | 프로젝트 정보, 씬 순서, 기본 스타일 관리 |
| 이미지 | `imageService` | 업로드, Sharp 최적화, 썸네일, scene 연결 |
| TTS | `ttsService`, `ttsJobService` | Gemini TTS 호출, PCM 수신, mp3 변환 저장, duration 추출, 캐시 |
| 프리뷰 | 프론트 `VideoPreviewCanvas` | 이미지/자막/배경을 9:16 캔버스에서 즉시 표시 |
| 타임라인 | 프론트 `SceneTimeline` | 씬 순서, duration, playhead, 전체 재생 |
| 렌더 | `renderService` | FFmpeg로 이미지+오디오+자막을 영상 파일로 생성 |
| 작업 상태 | `jobService` | pending/processing/completed/failed 상태 관리 |

#### 권장 데이터 모델

현재 `panels` 테이블을 바로 폐기하지 않고, MVP에서는 `panel = scene`으로 취급합니다. 이후 확장 시 `scenes`, `assets`, `scene_media`, `tts_jobs`, `render_jobs`로 분리합니다.

#### TTS 처리 흐름

1. 프론트가 선택 씬 또는 전체 씬의 TTS 생성을 요청합니다.
2. 백엔드는 `script + voice + speed + instructions + model`로 hash를 만듭니다.
3. 같은 hash의 완료된 오디오가 있으면 즉시 재사용합니다.
4. 없으면 `tts_jobs`를 `pending`으로 생성하고 작업 큐에 넣습니다.
5. 작업자는 Gemini TTS로 24kHz PCM 오디오를 생성하고 FFmpeg로 mp3 변환 후 `uploads/audio`에 저장합니다.
6. duration을 계산하고 씬의 `audio_url`, `durationMs`, `tts_status`를 갱신합니다.
7. 프론트는 polling 또는 Socket.io로 상태를 갱신합니다.

#### 렌더 처리 흐름

1. export 요청 전 누락된 대본, 이미지, 오디오를 검증합니다.
2. 씬별 이미지, 오디오, 자막 스타일, duration을 렌더 입력 JSON으로 정규화합니다.
3. FFmpeg로 씬 클립을 생성합니다.
4. 씬 클립을 순서대로 concat하고 전환 효과를 적용합니다.
5. 결과 mp4를 `uploads/renders`에 저장하고 다운로드 URL을 반환합니다.

#### MVP 단계의 의도적 제외

- 협업 편집
- 결제/구독
- 클라우드 스토리지
- 모바일 전용 편집 UX
- 고급 오디오 파형 편집
- 커스텀 보이스 생성
